# 误杀归因平台 · FP Attribution Platform

> 面向广告内容审核场景的**误杀（False Positive）归因分析平台**。
> 把机审误判的素材自动聚类，定位到具体审核标签与聚类簇，并沉淀为可复用的治理结论。

一句话概括业务价值：**让「机审拦错了」这件事，从一团模糊的投诉，变成可定位、可量化、可追责、可沉淀的数据链路。**

---

## ✨ 核心能力

| 模块 | 解决什么问题 |
|------|-------------|
| **总览大盘** | 大盘精度 / 绝对精度 / 误杀量等 KPI，周维度趋势，精度排行榜（按行业、元素类型），行业 × 元素 × 广告主交叉矩阵 |
| **标签跟踪** | 全部审核标签的精度分布与劣化预警，支持按元素类型下钻到具体样本 |
| **素材分类** | 按机审/人审判定双维度切分素材，快速定位分歧样本 |
| **聚类簇分析** | 对误杀素材自动聚类成簇，用「人机分歧七象限」定位簇的问题类型（双高一致 / 双低弱 / 人审分歧 / 机审分歧…） |
| **误杀 Case 分析** | 单条误杀的完整链路还原：素材预览、命中标签、审核时间线、相似样本召回 |
| **工单流转** | 误杀问题提需 → 打标（需要/无需）→ 转工单，形成闭环 |
| **结论沉淀** | 治理结论库，支持行业 / 问题分类 / 标签多维检索，可分享与导出 Word |
| **数据管理** | 数据导入导出、Excel / Word / PDF 报告生成 |

## 🛠 技术栈

| 层 | 选型 |
|----|------|
| 前端 | Vue 3.5 · Vite 7 · Vue Router 4 · Pinia 2 · ECharts 5 · TailwindCSS 3 |
| 后端 | Express 4 · Node 22（ESM） |
| 数据库 | SQLite（better-sqlite3）—— 单文件、零运维 |
| 其他 | 本地检索引擎（TF-IDF + 结构近邻，无外部依赖）· ExcelJS / docx / pdfkit 导出 |

**设计取向**：整个平台是**自包含**的——不依赖 MySQL、不依赖外部检索服务、不依赖任何内网组件，任意一台装了 Node 的机器都能跑起来。

## 🚀 快速开始

**环境要求**：Node.js **22 及以上**（`better-sqlite3@13` 需要 Node 22+，版本不匹配会导致启动崩溃）

```bash
# 1. 克隆
git clone <你的仓库地址>
cd mishapingtai

# 2. 安装依赖
npm install
cd server && npm install && cd ..

# 3. 构建前端
npm run build

# 4. 启动服务（默认端口 8787）
cd server && npm start
```

浏览器打开 **http://localhost:8787**

> 演示数据库已随仓库提供，**无需任何数据初始化**，启动即可看到完整平台效果。

## 📊 数据说明

数据规模**随实际接入自动变化**，平台不预设标签数、簇数或样本量上限。当前演示环境的数据快照：

| 项目 | 说明 |
|------|------|
| 审核标签 | 按业务标签体系动态生成 |
| 聚类簇 | 由误杀素材自动聚类产出 |
| 样本 / 精度记录 | 随每日数据接入持续累积 |
| 沉淀结论 | 随治理流程推进不断新增 |
| 数据周期 | 以实际接入范围为准 |

精度口径：
- **大盘精度** = `TP / (TP + FP)`，衡量机审整体判断水平
- **绝对精度** = `TP / (TP + FP_confirmed)`，仅计入人工复核确认的误杀，是更严格的口径

## 🧠 几个值得说明的设计决策

**1. 全平台统一数据底座**
所有面板（KPI、趋势、排行榜、交叉分析、钻取详情）一律从同一张样本表 `real_data_samples` 聚合，避免多数据源导致的口径打架——曾出现排行榜显示 100% 而 KPI 显示 66% 的问题，根因就是它们各读一张表。

**2. KPI 反映「当前状态」而非历史平均**
早期按全量加权平均算 KPI，会被历史低精度周拉低（精度呈上升趋势时，均值必然明显低于当前值）。KPI 卡片语义应为当前平台水平，历史演进交给趋势图呈现，两者分开后口径才合理。

**3. 聚类簇 ID 兼容**
历史数据簇 ID 为 `CL001` 格式，本库生成为 `c_1001_01` 格式，统一用 `UPPER(...) LIKE 'C%'` 匹配，避免过滤逻辑漏掉其中一类。

**4. 本地检索引擎**
「以图搜图 / 相似样本召回」不依赖外部向量服务，用 TF-IDF 余弦 + 结构化近邻 + 指纹近邻在本地完成，保证断网可用。

## 🌐 部署

平台是自包含的 Node + SQLite 应用，部署极其简单：

```bash
# 构建前端后，上传 server/ 与 dist/ 到服务器（同级目录）
cd server && npm install --omit=dev
npm start          # 或用 PORT=8080 npm start 指定端口
```

详细说明见 `deploy/README_DEPLOY.md`（含 systemd 开机自启、防火墙配置、备份方法）。

```
├── src/                  # 前端（Vue 3）

└── deploy/               # 部署包与部署文档
```
