## 二、交互逻辑链

### 2.1 状态机
```
submitted ──(handler.accept)──> accepted
accepted  ──(handler.conclude)─> concluded
concluded ──(submitter.adopt)──> done        ← 同步写 sediments
concluded ──(submitter.reject)─> rejected     ← 保留 handler
rejected  ──(handler 再改)─────> concluded
done      ──(submitter.reopen)─> concluded    ← 可重新改结论
```
- 处理人可改 `category`（问题分类），写时间线留痕，提需人可见。
- 采纳时 `result_type`：real_fp（真实误杀）/ machine_right（机审正确）。

### 2.2 新建提需流程
```
AnalysisView/PreviewAnnotate 勾选素材 → ticketFlow.begin() + setSamples
  → router.push('tickets')
onMounted: ticketFlow.active && samples → 带入 form.samples，用 tagContext 自动填充字段
  → openNew()
step1 选素材 → step2 autoFields() 自动带出 标签/元素类型/行业/审核人/创意ID/广告主ID/指纹
  → syncAutoTitle() 自动标题（标签|元素类型|行业）
step3 写描述 + 紧急度 + 通知对象 → submitTicket()
  → ticketApi.create → 写 tickets + timeline + 企微通知
```
- 关闭弹窗：`newOpenProxy` 代理，主动取消且存在来源页则 `ticketFlow.cancel()` 返回来源。

### 2.3 处理结论
```
openHandle(t) → 初始化 handleForm + 逐条 sampleConclusions/sampleNeedTags
提交结论 → ticketApi.conclude(conclusion, handleReason, needTag, conclusionImages, isQualified, handleRemark, category)
  → 写 tickets + timeline + 企微通知（@处理人选的人/提需指定人）
```

### 2.4 采纳联动沉淀库（关键跨模块）
```
ticketApi.adopt(category, categoryNote, resultType)
  → 后端查询是否已有 sediment（ticket_id 匹配）
  ├─ 有 → UPDATE sediments
  └─ 无 → INSERT sediments（title/type/category/result_type/tag_id/tag_name/industry/submitter/handler/samples/descr/conclusion/fp_reason/related_materials/handle_info/四字段）
  → 企微通知采纳
```

## 三、UI 设计要点

- 视角切换 seg（提需人/处理人），红点提示「待采纳」。
- 提需人：普通列表（tab 分档）+ 搜索。
- 处理人：行业分组卡（可抢单数角标）→ 点分组展开该组工单列表。
- 工单行展开：工单信息 + 素材缩略图网格（≤3 默认，展开全部）+ 操作（受理/结论/采纳/退回/重开/删除/预览/导出）。
- 新建提需：三步 Modal（①选素材 ②字段自动带出 ③描述/紧急度/通知）。
- 处理结论 Modal：结论文本 + 图片拖拽上传（512KB/6张） + 逐条素材结论 + 是否需要打标 + 问题分类下拉 + 备注。
- 素材预览 Modal：大图/视频 + 左右切换（键盘 ←/→）。
- 分享按钮 + 企微 `?t=` 跳转自动定位展开。

## 四、前端实现（关键代码位置）

### 4.1 API（ticketApi）
```js
list / detail(id) / create / accept(id) / conclude(id, data) /
adopt(id, data) / reject(id, data) / reopen(id) /
remove(id) / notifySuggests(q) / exportExcel(id)
```

### 4.2 关键状态
- `persp`：视角（submitter/handler），持久化。
- `curTabs`/`filtered`：按角色切换 tab 定义。
- `industryGroups`/`groupTickets`：处理人行业分组。
- `overlayState`：持久化当前打开的工单ID/素材ID（跨设备还原）。
- `materialList(t)`：工单素材标准化（优先 samplesData，无则按 sampleCount 占位）；`matStatus` 判定（consistent/fp/revised/remarked/pending）。
- `ticketFlow` store：提需流程态（active/samples/origin），跨模块传递素材。

### 4.3 字段自动带出
- `autoFields()`：从首条素材取 tagId/tag/elementType/industry/reviewer/dcId/advertiserId/fingerprint。
- `buildAutoTitle()`：标签|元素类型|行业 自动拼接标题。

## 五、后端实现（tickets.js）

| 路由 | 方法 | 要点 |
|------|------|------|
| `/` | GET | 按角色返回工单（admin 全量；handler 公共池+自己；submitter 自己） |
| `/notify-suggests` | GET | 从历史 notify_users/submitter/handler 提取去重联系人（须在 `/:id` 前注册） |
| `/:id` | GET | `withTimeline` 补全 samples_data 四字段（dcId/opsAdvertiserName/fingerprint/reviewerName） |
| `/` | POST | 新建（ensureTicketColumns 动态加列；ID=`TKT-${2053+seq}`；写 timeline；企微通知） |
| `/:id/accept` | POST | 处理人受理（status=accepted，SLA 计时） |
| `/:id/conclude` | POST | 提交结论（可改 category 写 timeline）；企微通知 |
| `/:id/adopt` | POST | 采纳 + 同步 sediments（新增/更新）；企微通知 |
| `/:id/reject` | POST | 退回（原因必填，status=rejected 保留 handler）；企微通知 |
| `/:id/reopen` | POST | 重开（done→concluded）；企微通知 |
| `/:id/export` | GET | Excel 两 sheet（工单字段 + 素材明细） |
| `/:id` | DELETE | 管理员删工单 + 时间线 |

### 5.1 `withTimeline(ticket)`
- 解析 `samples_data` JSON → 按 `element_fingerprint/media_url` 从 `ai_evaluate_detail` 补全 22 个标准字段（dc_id/ops_advertiser_name/fingerprint/reviewer_name/agency_uid/agency_name/model_version/arrive_time/ds/class_num/class_id/ocr/asr/uid/uid_name/element_type/element_type_name/行业 等）。
- 提取工单级四字段（取首条样本）。
- 返回 timeline 数组。

### 5.2 动态列（ensureTicketColumns）
首次写前确保列存在：`conclusion_images/is_qualified/handle_remark/result_type/samples_data/notify_users/dc_id/ops_advertiser_name/element_fingerprint/ai_evaluate_reviewer_name`。

### 5.3 企微通知（wecomNotify.js）
- `notifyTicketCreated/TicketConcluded/TicketAdopted/TicketRejected/TicketReopened`。
- `@` 通知对象（`notify_users` JSON 数组）。
- Webhook 地址来自环境变量 `WECOM_WEBHOOK_URL`（当前代码已就绪待配置）。

## 八、改造注意事项

1. **最大前端文件**：TicketsView 2316 行，建议按「列表/新建/处理/预览/分享/导出」拆子组件，降低改造风险。
2. **采纳联动沉淀**：`adopt` 会写 `sediments`，改造工单字段（如新增结论维度）需同步 sediments 字段，否则沉淀库缺数据。
3. **samples_data 四字段补全**：`withTimeline` 依赖 `ai_evaluate_detail` 22 字段，结构变更需同步 `BASE_FIELDS` 与补全逻辑。
4. **状态机不可绕跳**：reject 仅 concluded 可、reopen 仅 done 可，改造状态流需保持守卫。
5. **企微通知待配置**：`WECOM_WEBHOOK_URL` 未配置时不报错（catch 静默），上线前需配置。
6. **动态加列**：`ensureTicketColumns` 兼容旧表，新增工单字段建议直接进 schema.js DDL 而非依赖运行时加列，便于部署一致。
7. **跨模块来源返回**：提需流程 `ticketFlow.origin` 记录来源页（分析/分类），取消/提交后正确返回；改造导航需保持该链路。
