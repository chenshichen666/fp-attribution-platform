# 模块五 · 公共支撑与数据口径

> 跨四大模块复用的机制：时间窗口方案A、数据口径（查准率）、分享快照、相似检索（TRAG）、媒体预览三层兜底、状态持久化、鉴权与数据模式分流、UI 状态跨设备延续。

## 一、时间窗口方案 A（全模块联动核心）

**决策来源**：用户确认采用「方案 A」（时间窗口变化 → 标签精度 / 整体样本数 / FP 数据全部联动）。

### 1.1 前端
- 组件：`src/components/DateRangeFilter.vue`，`v-model` 输出 `{preset, start, end}`。
- 各模块持久化键：
  - 分析：`analysis:globalDate`（AnalysisView）、`tagDetail:tagDate`（TagDetailView）
  - 分类：`classify:tagDate`（ClassifyView）
  - 沉淀：`sediment:sedDate`（SedimentView，当前仅 UI 态）
- `dateRange()` 工具：有 start/end 即转查询参数，否则返回 `{}`。

### 1.2 后端判定（`server/src/routes/tags.js`）
```js
async function useSampleAggregation(req) {
  const start = ..., end = ...
  if (!start && !end) return false              // 无窗口 → 聚合表
  const range = await getSampleRange()          // real_data_samples arrive_time 真实范围（5min缓存）
  if (s <= range.min && e >= range.max) return false  // 覆盖全量 → 聚合表
  return true                                    // 子集 → 样本明细实时聚合
}
```
- 子集聚合：标签精度 = `(COUNT(*) - SUM(is_fp)) / COUNT(*) × 100`；FP=`SUM(is_fp)`；整体样本数随之变。
- 空 `arrive_time` 放行（`sampleTimeWhere` 中 `arrive_time IS NULL OR ''` 不排除）。

### 1.3 改造约束
- **双分支一致性**：任何精度/样本数/FP 计算改动必须同时覆盖「聚合表分支」与「样本明细分支」，否则切换时间窗口数值跳变。
- **精度表 arrive_time 语义不同**：`real_data_tag_precision.arrive_time` 是上传当天（非业务日），时间过滤会错误排除标签；故精度表不做时间过滤（仅 `real_data_samples` 按 arrive_time 过滤）。
- **覆盖全量不跳变**：窗口覆盖数据全量范围视为「全部时间」，走聚合表，避免「205 ↔ 88 子集」跳变。

## 二、数据口径（查准率 / 误杀率）

- 查准率 = `TP / (TP + FP) × 100%` ≡ `(总样本 − FP) / 总样本 × 100%`。
- 误杀率 = `100% − 查准率`。
- 精度聚合表 `real_data_tag_precision` 自带 `tp/fp/fp_conf/tn/fn/precision_val`，后端优先级：
  ```
  SUM(tp)/NULLIF(SUM(tp)+SUM(fp),0)
  → SUM(precision_val*total)/SUM(total)
  → (SUM(total)-SUM(fp))/SUM(total)
  → 0
  ```
- 状态档位（`src/data/mock.js` tagStatus）：null/''/NaN→无数据(gray)；<50→异常(red)；<85→关注(orange)；≥85→正常(green)。
- 整体样本数：`fp + tp`（精度聚合表），非 `sample_count` 直接求和。

## 三、分享快照（跨模块复用机制）

- 分析 `ShareButton`（analysis）、工单（tickets）、沉淀（sediment）均支持「复制此页面」UI 状态快照。
- API：`shareApi.create(payload)` / `shareApi.get(id)`。
- 分类模块额外：自包含快照存 `classify_shares` 表（脱 tagId 只读还原 + 另存为副本）。
- 实现：`src/utils/share.js`（`getShareIdFromUrl`/`openShare`）+ 各模块 `xxxShareState()`/`applyXxxShare()`。
- 持久化键示例：`tickets:overlay`、`sediment:detailOverlay`、`analysis:globalDate` 等。

## 四、相似素材检索（TRAG）

- 前端：`src/components/TragSearchModal.vue`（统一弹窗，见分类模块）、`src/views/classify/PreviewAnnotate.vue` 中 hover 预热 + 打开即搜。
- 任务自动探测（`autoDetectTaskLocal`）：
  - 文本 → `text_text`
  - 图片有 OCR → `image_ocr`（优先，稳定）；否则 `image_image`（依赖 Venus 视觉嵌入，常 500）
  - 视频有 OCR → `video_ocr`；有 ASR → `video_asr`；有指纹 → `video_video`；否则 `video_frame`
- 后端：`server/src/routes/trag.js`：
  - `/trag/tasks`：永远降级返回静态 7 任务列表（TRAG 不可用也不抛 5xx）。
  - `/trag/search`：先 `getServiceUrl()` 可用性检查；不可用返回 503；查 `trag_cache`（24h）共用缓存；调用 Python 微服务；`enrichResultsWithTags` 补标签ID/名。
- Python 微服务：`server/trag_service/`（FastAPI，`main.py`/`trag_client.py`）。
- `server/src/trag/manager.js`：`getServiceUrl/getStatus/markUnhealthy` 健康探测 + 自动恢复，根本消除 ECONNREFUSED。

## 五、媒体预览三层兜底（全站统一）

- 公共层：`src/utils/mediaPreview.js`（文件名已含方案 A 三层架构）：
  1. `previewSrc()` 直连 CDN（含 `dis_t` 续期 + http→https 升级）。
  2. `proxyUrl()` 经后端 `/api/media-proxy`（服务端腾讯内网续期 `dis_t` 代拉）。
  3. `onMediaError()` 失败显示「↗ 原素材」新标签（`openOriginal()`）。
- 微信视频等必须签名 CDN 直连即失败，跳过代理走终路径。
- 指令层：`v-lazy-img` / `v-lazy-video` / `v-lazy-media`（src/directives/）统一复用。
- 各模块 `onMediaErr`/`safeUrl` 仅薄封装，逻辑在公共层。

## 六、状态持久化（跨设备延续）

- `src/utils/usePersistedRef.js`：
  - `usePersistedRef`：localStorage。
  - `useRemotePersistedRef`：服务端镜像（`/api/ui-state`）按 `eng+key` 持久化，换设备/重装可恢复。
- 各模块筛选/排序/分页/弹窗态均用 remote 持久化键（如 `analysis:kw`、`tickets:tab`、`sediment:catFilter`）。

## 七、鉴权与数据模式分流

- 鉴权：`server/src/middleware/auth.js`（`requireLogin`/`requireRole`/`requireRole(...,'admin')`/`audit`），注入 `req.currentUser`（来自 tauth/info，前端经 `authHeaders()` 传 `x-user-eng/name/team`）。
- 数据模式：`server/src/middleware/dataMode.js`（`rewriteDataTables`）按 `x-data-mode`（draft/formal）改写表名，With 预览域名走草稿表、线上走正式表。
- 角色：`users` 表（roles 逗号分隔），`permission_requests` 审批流；前端 `src/stores/auth.js`。

## 九、改造总风险清单（跨模块）

1. **时间窗口方案A 双分支**：改动精度/样本/FP 口径必须同步 `useSampleAggregation` 两分支。
2. **聚合表 vs 样本明细 语义差异**：`arrive_time` 语义不同（上传日 vs 业务日），勿混用时间过滤。
3. **去重 rawTotal**：前端依赖 `rows.rawTotal` 非枚举属性，后端 samples 路由必须 `Object.defineProperty` 挂载。
4. **标签名补全**：精度表 `tag_name` 常空，依赖 `real_data_tags` 字典；改标签体系保持 `tag_id` 一致。
5. **媒体预览三层兜底**：任何素材展示改造必须复用 `mediaPreview.js`，勿硬编码直连或代理。
6. **工单↔沉淀联动**：改工单字段（结论维度/四字段）必须同步 `tickets.js` adopt 的 sediments 写入。
7. **分享快照**：分类 `classify_shares` 自包含只读，改造权限勿让只读态写回。
8. **持久化键命名**：跨设备延续依赖固定键名，改名需同步前后端与 `ui_state` 旧数据兼容。
9. **导出 16 列一致性**：`generateExcel`（tags.js 与 classifyUpload.js 各一份）结构需同步维护。
10. **TRAG 可用性**：检索改造必须保持 `/tasks` 静态降级与 503 友好提示，避免 ECONNREFUSED 透传。
