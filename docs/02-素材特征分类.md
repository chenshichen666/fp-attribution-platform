# 模块二 · 素材特征分类

> 前端：`src/views/classify/ClassifyView.vue`（标签栏+上传+分享）、`PreviewAnnotate.vue`（素材网格+分类+标注+检索）、`scriptClassify.js`（脚本预分类）、`ChatClassify.vue`（AI 对话分类）
> 后端：`server/src/routes/materials.js`（分类CRUD/结论/导出）、`classifyUpload.js`（上传数据）
> 核心表：`material_category`、`material_category_relation`、`material_conclusion`、`uploaded_classify_data`、`uploaded_classify_history`、`classify_shares`

## 二、交互逻辑链

### 2.1 主流程（ClassifyView → PreviewAnnotate）
```
onMounted:
  ├─ tagApi.list() 拉标签候选
  ├─ loadUploadHistory() 拉上传历史
  ├─ 路由参数 q.tagId → 自动填充标签+时间窗口 → 自动 loadTag
  └─ q.share → loadShare(shareId) 只读还原
onActivated(keep-alive): 刷新上传历史 + 响应路由参数变化
watch(classifyDate): 非路由初始化态 → 平台数据 reloadByDataSource
```

### 2.2 上传数据流程（classifyUpload.js）
```
triggerUpload → handleFileUpload
  ├─ XLSX 读文件 → sheet_to_json
  ├─ 列名映射（到达时间/AMS行业/审核元素类型/审核标签ID/AI评测人审标签/审核元素值/指纹/ocr/asr/class_num/分类/补充说明）
  ├─ 解析出全部标签（machineTag 逗号拆分）→ parsedTags（按频次排序，默认选中最多）
  ├─ 弹窗 confirmTagAndUpload
  └─ doUpload → classifyUploadApi.upload
        ├─ 全失败 → 回滚事务
        ├─ 部分失败 → partialFailure + failedBatches + _uploadRetryContext
        └─ 成功 → 切数据源=upload，载入 samples
retryFailedUpload: 仅重传 failedBatches 内样本
```
**覆盖策略**：同一标签多次上传先 `DELETE` 旧数据再插新（事务内）。

### 2.3 一键预分类（scriptClassify.js 两阶段）
```
scriptPreClassify():
  ├─ clearAllCats() 清空旧自动分类
  ├─ Phase1: 按 classId 分组（noise→噪声，空→classNum 分组）→ ensureCatByName 建分类 → 归素材
  └─ Phase2: setTimeout 链逐个分类 generateFeatureForGroup
        ├─ extractKeywords (2~20字 ngram, 停用词/边界过滤, 频次阈值)
        ├─ extractPhrases (5~40字句式)
        ├─ dedupSimilarWords (子串自适应去重)
        └─ onFeature(idx, {featureBrief, featureDetail, sampleSnapshot}) → 写后端 + 响应式刷新
```
命名：`聚类簇 N` / `分类N` / `噪声数据` / `未聚类`。

### 2.4 归类与标注落库
- `assignOne(r)`：`matchKey` 取同素材所有 sibling sampleId → `materialApi.assign` 写 `material_category_relation`。
- `matchKey` 优先级：`指纹 > 归一化 mediaUrl > ocr+asr 文本`。
- `syncAnnotationAcrossArrays`：去重/全量双数组同步，保证前端一致。

### 2.5 分享快照
- `copyShareLink`：`buildShareSnapshotLocal`/`previewRef.buildShareSnapshot` 取 cats+samples+view → `shareApi.create` → 写入 `classify_shares`，生成 `#/classify?share=xxx` 链接。
- `loadShare`：脱 tagId 只读还原；`forkShareToMine` 在可写标签上写回。

## 三、UI 设计要点

- 页头「素材特征分类 / 自动提取特征并进行分类，最大程度减少人工耗时 / 基于FP数据」。
- 标签栏：标签输入 + 一键加载 + 时间窗口 + 上传数据入口（上传/重试/历史/清空）+ 数据源切换（平台/上传，上传点亮绿点）+ 分享快照按钮。
- 上传历史折叠面板：表格展示；标签选择弹窗（radio 列表，显示系统内/未在标签库）。
- 素材 URL 卡片：textarea + 加载/清空/过期选择/复制快照；可折叠。
- PreviewAnnotate：
  - 归因分类区：新增输入 + 分类卡片（名称/特征/数量/展开编辑/删除）。
  - 分类概况区：脚本预分类结果（source=auto）。
  - 筛选条：类型/一级行业/二级行业（联动）/审核人/广告主/人审标签/仅已标注 + 列数切换 + 展示模式（全部/按分类）。
  - 素材网格：`gridTemplateColumns: repeat(cols, minmax(150px,1fr))`，卡片含缩略图（懒加载 img/video）、类型标签、机审/人审标签、归类下拉、画面特征/补充说明可编辑、勾选框。
  - 分页分片：`pageSize=50`，`loadMore` 增量渲染。
  - 选择浮条 + 底部导出/发起提需。
- 详情弹窗 `TragSearchModal`：相似检索结果 + 归类 + 补充编辑 + 视频播放（与卡片同步）。

## 四、前端实现（关键代码位置）

### 4.1 API
```js
// materialApi（src/api/index.js）
categories: (tagId) => GET  /materials/:tagId/categories
addCategory / updateCategory / removeCategory
assign: (tagId, items) => POST /materials/:tagId/assign
getConclusion / saveConclusion
exportWord(tagId, data) / exportPdf(tagId, data)

// classifyUploadApi
upload / retryFailed / uploadBatch
getStatus(tagId) / getSamples(tagId) / getHistory(tagId)
clearAll / clearTag(tagId)
exportExcel(tagId, {sampleIds})
```

### 4.2 PreviewAnnotate 关键状态
- `rows`：归一化素材行（含 `categoryId/featureDesc/supplement/open`）。
- `cats`：全部分类；`attrCats`（source≠auto/ai_optimize）、`overviewCats`（source=auto/ai_optimize）。
- `overviewStat`/`attrStat`：实时统计各分类数量/占比。
- `displayMode`：all / byCat；`grouped` 按分类分组（含「未归类」）。
- `videoStates`：响应式播放状态同步。
- `_rawRows`/`_dedupedRows`：去重双数组，标注归一化跨数组同步。

### 4.3 媒体判定
- `isVideoByUrl`/`isImageByUrl`/`resolveIsVideo`：以 URL 实际扩展名为准，避免 `ads_svp_video__xxx.jpeg` 误判视频黑屏。
- `normUrl`：去签名+http→https 归一，用于去重与分享快照。

## 六、数据库表结构

### 6.1 `material_category`（归因分类）
```
id, tag_id, name, feature, feature_brief, feature_detail, sample_snapshot,
source('manual'|'upload'|'auto'|'ai_optimize'), owner, is_demo, created_at, updated_at
```

### 6.2 `material_category_relation`（素材↔分类归属 + 可编辑内容）
```
id, tag_id, sample_id, media_url, category_id, feature_desc, supplement, owner, is_demo, updated_at
UNIQUE(tag_id, sample_id)
```

### 6.3 `material_conclusion`（分类结论）
```
id, tag_id, tag_name, content(MEDIUMTEXT), summary, owner, is_demo, created_at, updated_at
```

### 6.4 `uploaded_classify_data`（用户上传数据，覆盖策略）
```
id, tag_id, tag_name, sample_id, element_type, element_type_name, is_video,
policy_ids, ai_evaluate_policy_ids, first/second_level_industry_name, media_url,
ocr_content, asr_content, class_num, class_id, uid, arrive_time, ds,
element_fingerprint, dc_id, ops_advertiser_name, ai_evaluate_reviewer_name,
is_fp(默认1), batch_id, uploaded_by, uploaded_at
```

### 6.5 `uploaded_classify_history` / `classify_shares`
- history：上传记录（tag/文件/条数/分类数/人/时间）。
- classify_shares：分享快照（`payload MEDIUMTEXT` 自包含 cats/samples/view，`expire_days`）。

## 八、改造注意事项

1. **PreviewAnnotate 超大文件**：1976 行，改造建议按「分类管理 / 标注 / 筛选展示 / 检索 / 导出 / 提需 / 分享」拆分为子组件/组合式函数，避免单文件继续膨胀。
2. **覆盖策略**：上传为「先删后插」，多用户并发上传同一标签需防 Race（当前事务内 DELETE+INSERT 但非锁表）；改造如需保留历史版本需改策略。
3. **分类 source 语义**：`manual/upload/auto/ai_optimize` 决定展示分区（归因 vs 概况）；一键预分类前会 `clearAllCats` 清掉旧 auto，不影响 manual。
4. **去重双数组**：`matchKey` 一致是标注同步的核心，任何素材唯一键改动（如指纹缺省策略）都需同步 `_rawRows/_dedupedRows/syncAnnotationAcrossArrays`。
5. **导出列固定 16 列**：`generateExcel`（tags.js 与 classifyUpload.js 各一份，结构需保持一致）；改造导出字段需两处同步。
6. **分享快照自包含**：`classify_shares.payload` 脱离 tagId 存储，脱敏/权限改造时注意只读态 `shareMode` 禁止写回。
7. **AI 对话分类（ChatClassify）**：走 KNOT 智能体，属补充路线，改造主线时勿遗漏该入口。
8. **时间窗口不作用于上传数据**：`watch(classifyDate)` 仅平台数据重载；上传数据忽略时间窗口（见 `reloadByDataSource` 分支）。
