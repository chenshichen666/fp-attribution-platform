## 二、交互逻辑链

### 2.1 标签概况页（AnalysisView）
```
onMounted(loadData)
  ├─ 首次：dataMetaApi.get() 探测数据是否上传
  │     └─ 未上传 → 空态，不请求标签
  │     └─ 已上传 → tagApi.overview({}) 探数据实际日期范围(dataMinDate~dataMaxDate)
  │            └─ 用实际范围初始化 globalDate（initializing 标志防 watch 重复触发）
  ├─ tagApi.list(range) 拉标签列表（range 来自 globalDate）
  ├─ tagApi.overview(range) 拉 KPI
  └─ analysisStore.setData(...) 写入 store 供 TagDetail 复用
watch(globalDate) → 非初始化态 → loadData() 重新聚合
```

### 2.2 时间窗口 × 精度联动（方案 A）
- 前端 `dateRange()` 把 `globalDate {start,end}` 转为查询参数。
- 后端 `tags.js` 的 `useSampleAggregation(req)` 判定：
  - 有 start/end 且为数据全量子集 → 返回 true → 从 `real_data_samples` 按 `arrive_time` 实时聚合。
  - 否则 → 从 `real_data_tag_precision` 聚合表取全量快照。
- 精度计算：`prec = (COUNT(*) - SUM(is_fp)) / COUNT(*) × 100`。

### 2.3 标签下钻（TagDetailView）
```
onMounted(loadData)
  ├─ tagApi.detail(id) 取标签聚合
  ├─ tagApi.samples(id, {}) 取 FP 素材（默认全量）
  └─ tagApi.overview({}) 静默初始化 tagDate
watch(route.params.id) → 切换标签重置时间窗口重新加载
watch(tagDate) → 按时间范围重拉 samples
```
- 明细来自 `real_data_tag_precision_samples`（is_fp=1）；空则回退 `real_data_samples`（is_fp=1）。
- 标签匹配：`tag_id` 精确 OR `policy_ids`/`ai_evaluate_policy_ids` 复合成员命中（逗号边界避免 14795 误命中 147950）。
- 去重：按 `指纹 > 归一化 media_url > sample_id`，`rows.rawTotal` 携带去重前真实总数。

## 三、UI 设计要点

- 页面主标题「误杀样本分析」，副标题说明自动统计与下钻定位。
- 空态条：图标 + 说明 +（管理员）跳转数据管理按钮。
- KPI 行：4 卡栅格（`repeat(4,1fr)`，<900px 降为 2 列），`KpiCard` 组件带图标/颜色。
- 全局时间窗口：右上角 `DateRangeFilter`（preset 近N天 + 自定义起止）。
- 柱状图卡片：标题 + 图表筛选（标签ID/名搜索 + 精度排序 select）。
- 明细表：表头分区（状态点 + 精度条 + 排序序号）；分档 seg-tabs 带数量角标；备注/归因列行内 input。
- 标签详情：返回条（sticky）+ 页头（标签ID/状态徽章/标签名 + 去素材特征分类按钮 + 时间窗口）；环形仪表 + 2 张 mini-KPI；分布图组（行业 span2 + 元素类型饼图）；方案设计阶段三图（广告主/审核人/人审标签）；明细表带元素值预览列（img/video 懒加载 + OCR/ASR 折叠 + 指纹）。
- 选择浮条：底部 fixed，显示已选数 + 清空 + 发起提需/导出选中。

## 四、前端实现（关键代码位置）

### 4.1 API 封装（`src/api/index.js` — tagApi）
```js
export const tagApi = {
  list: (q) => api.get(`/tags${qs(q)}`),
  detail: (id) => api.get(`/tags/${id}`),
  overview: (q) => api.get(`/tags/overview${qs(q)}`),
  samples: (id, q) => api.get(`/tags/${id}/samples${qs(q)}`),
  trend: (id, q) => api.get(`/tags/${id}/trend${qs(q)}`),
  exportExcel: (id, data) => downloadBlob(`/tags/${id}/export/excel`, data, `tag-${id}-fp-export.xlsx`),
}
```
所有请求经 `authHeaders()` 注入 `x-user-eng/name/team` 与 `x-data-mode`（draft/formal 分流）。

### 4.2 状态档位（`src/data/mock.js` — tagStatus）
```js
// null/''/NaN → 无数据(gray)
// <50 → 精度异常(red)
// <85 → 精度关注(orange)
// 其余 → 精度正常(green)
```

### 4.3 关键 computed
- `filtered`：分档 + 关键词；默认随机呈现中间段（排除 ≥95% 与 ≤0%），不落入排序分支。
- `chartTags`：图表专用筛选，最多 20 条。
- `liveKpi` / `kpi`：KPI 直连 overview 返回。
- TagDetail `fpSamples`：仅 `isFp` 素材参与分布统计。
- `distByIndustry/distByAdvertiser/distByReviewer/distByHumanTag`：各类分布聚合（前端实时算）。

## 五、后端实现（tags.js 关键路由）

| 路由 | 方法 | 逻辑要点 |
|------|------|----------|
| `/tags` | GET | 方案A分支：聚合表 vs 样本明细实时聚合；`nameMap()` 补标签名；`rank` 排序 |
| `/tags/overview` | GET | KPI 聚合；5 分钟进程内缓存（`overviewCache`）；并行查 ds/meta/range |
| `/tags/:id` | GET | 单标签聚合（供 TagDetail，避免全量 find） |
| `/tags/:id/samples` | GET | FP 素材；主表 `real_data_tag_precision_samples` 空则回退 `real_data_samples`；LEFT JOIN 补 4 字段；去重带 rawTotal |
| `/tags/:id/trend` | GET | 按 `date`/`ds` 聚合精度趋势 |
| `/tags/:id/export/excel` | POST | 生成 16 列 Excel（含分类/补充说明），回退表查询 |
| `/tags/rebuild-url-index` | POST | 手动重建 `ai_evaluate_detail_url_idx` 索引表（性能优化） |

### 5.1 关键函数
- `useSampleAggregation(req)`：时间窗口是否命中子集（核心分支开关）。
- `sampleTimeWhere(req)`：`arrive_time` varchar 用 `DATE()` 规范化，空值放行。
- `timeWhere(req)`：精度聚合表无需时间过滤（返回空）。
- `parseIds/rowConsistent`：标签 ID 清洗与整行一致性判定。
- `nameMap()`：`real_data_tags` 取 `tag_id→tag_name` 字典补全。
- `mapElementType()`：元素类型枚举→中文。
- `generateExcel()`：16 列表头，`feature/class_num/分类/补充说明` 等。

## 六、数据库表结构（相关字段）

### 6.1 `real_data_tag_precision`（精度聚合表，全量快照）
```
id, tag_id, tag_name, total, fp, precision_val(DECIMAL5,2),
tp, fp_conf, tn, fn, sample_count,
first_level_industry_name, second_level_industry_name,

element_fingerprint, remark, fp_reason
```
索引：`idx_tag(tag_id)`。

### 6.2 `real_data_samples`（样本明细表，方案A子集聚合源）
```
id, tag_id, tag_name, sample_id, element_fingerprint, dc_id, element_type,
is_video, policy_ids, ai_evaluate_policy_ids,
first_level_industry_name, second_level_industry_name, media_url,
ocr_content, asr_content, class_num, class_id, uid,
ops_advertiser_name, ai_evaluate_reviewer_name, arrive_time(VARCHAR), ds,
is_fp, fp_reason, remark
```
索引：`idx_tag`、`idx_fingerprint`。

### 6.3 `real_data_tag_precision_samples`（精度样本明细，FP 主源）
与 `real_data_samples` 字段对齐，含 `is_fp`；优先于 samples 表读取。

### 6.4 关联表
- `ai_evaluate_detail_url_idx`：按 `element_value_norm`（去签名裸 URL）聚合的补充字段索引表，`/tags/rebuild-url-index` 重建。
- `cluster_data`：聚类兜底（class_id 查找），`material_category_relation` 标注 JOIN。

## 八、改造注意事项

1. **精度口径双分支**：任何精度/样本数/FP 计算的改动必须在 `useSampleAggregation()` 两条分支（聚合表 + 样本明细）同时验证，避免切换时间窗口时数值跳变。
2. **备注/归因未落库**：`AnalysisView` 的 `t.remark`/`t.fpReason` 行内编辑当前仅前端内存态，刷新即丢；若需持久化需新增后端接口（可考虑写入 `real_data_tag_precision.remark/fp_reason`，但注意它是聚合行，多人并发编辑需约定）。
3. **空 arrive_time 放行**：`sampleTimeWhere` 对空值放行是特意设计（部分 FP 无到达时间），改造勿误删。
4. **去重 rawTotal**：前端依赖 `rows.rawTotal`（非枚举属性）显示「真实总样本」，后端 `samples` 路由必须用 `Object.defineProperty` 挂载。
5. **标签名补全**：精度表 `tag_name` 常空，依赖 `real_data_tags` 字典；改造标签体系时保持该表与精度表 `tag_id` 一致。
6. **overview 缓存**：5 分钟 TTL，改造后若数值异常先排查缓存（`overviewCache`）。
